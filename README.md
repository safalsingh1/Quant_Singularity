## Quick Start

### 1. Data Audit (FIRST — before any training)
```powershell
python data_audit.py
```
Produces `audit_report.txt` and `slm_intern_data/finetune_instructions_clean.jsonl`.

### 2. Validate Eval Pipeline (before training)
```powershell
python eval_suite.py mock
```
Runs mock random-pod evaluation to confirm eval machinery works.

### 3. Local GPU Training
```powershell
python finetune_local.py
```
Auto-detects CUDA. Uses 4-bit quantisation if GPU available. Saves adapter to `adapter/`.

### 4. Kaggle Training
Upload `slm_intern_data/` as a Kaggle dataset and run `finetune_kaggle.py` on T4.

**Kaggle Notebook URL:** `[ADD URL AFTER UPLOAD]`

### 5. Evaluation (with and without RAG)
```powershell

python run_eval.py --device cuda

python run_eval.py --device cpu --no-4bit

# Mock eval only (no adapter needed)
python run_eval.py --mock
```

## Key Design Decisions

### Base Model: TinyLlama-1.1B
Chosen over Phi-2 (2.7B) because:
- Fits comfortably in Kaggle T4 VRAM with 4-bit quantisation
- `chat-v1.0` checkpoint already instruction-tuned (better starting point for SFT)
- Inference on CPU remains <3s per signal at 4-bit

### LoRA Configuration
| Param | Value | Rationale |
|---|---|---|
| rank | 8 | Balanced for 261 samples; rank=4 under-fits, rank=16 over-fits |
| alpha | 16 | 2×rank — stable gradient scaling |
| dropout | 0.05 | Light regularisation on small dataset |
| target modules | q_proj, v_proj | Attention value matrices; standard for TinyLlama |

### Conviction Field Design
The conviction value is **not** a softmax probability over direction tokens. Softmax P(token|prefix) reflects linguistic probability, not calibrated signal confidence. Instead:
- Conviction is a numeric target in supervised training (the model learns to generate a float)
- Post-hoc calibration measured via ECE (Expected Calibration Error)
- Thresholds pre-committed: ECE < 0.20 is acceptable

### Orchestrator Rules (fixed per brief)
1. **ADX < 20** → suppress entirely, return NEUTRAL, do not call pod
2. **Parse failure** → return NEUTRAL, log raw output  
3. **Conviction < 0.40** → downgrade direction to NEUTRAL

Every decision is logged with reason code + triggering values to `orchestrator_decisions.jsonl`.

## Data Audit Summary

**Critical Finding:** 39 of 300 training rows (rows ~48–92) had the `conviction` field serialised as human-readable text (`"high"`, `"moderate"`, `"low"`, `"strong"`, `"weak"`) instead of a float. Additionally, 6 rows had partially parseable strings like `"0.8 (high)"`.

**Decision:**
- 39 uncorrectable rows **excluded** (would teach schema non-compliance)
- 6 correctable rows **patched** (leading float extracted, validated)  
- Final clean set: **261 rows**

See `audit_report.txt` for full breakdown.

## Eval Thresholds (Pre-committed)

| Metric | Threshold | Type |
|---|---|---|
| Schema pass rate | ≥ 0.95 | Hard fail below |
| Global directional accuracy | ≥ 0.45 | Target |
| Per 5-day window accuracy | ≥ 0.38 | Review if below |
| Conviction ECE | ≤ 0.20 | Calibration |
| Parse failure rate | ≤ 0.02 | Hard fail above |
